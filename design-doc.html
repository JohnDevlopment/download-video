Download Video as a project defines jdv as a commandline application for downloading videos and OSTs.

1 Terminology

From this point in the document, the following definitions apply:

Video
A file that contains any combination of a video stream or an audio stream.
Site processor
A singleton class that handles site-specific implementations of the SiteProcessor interface.

2 User Interface

jdv has three commands:

  • video for downloading videos
  • ost for downloading OSTs
  • config for setting/getting config variables

2.0.1 Global Options

Short Long Note
  --debug Enter debug mode.

2.1 video

Downloads videos from the internet using several criteria to filter formats. 

Usage:
  jdv video [-hny] URL
  jdv video [-hny] [--height HEIGHT] [--video-only] URL
  jdv video [-hny] [--audio-only] URL
  jdv video [-hny] -r FILE

The lone positional argument is treated as a string URL unless -r is passed, in which case it is treated as a path.

2.1.1 Options

Short Long Note
-n --dry-run Prints only what will happen.
-r --rename Renames the file instead of downloading from URL.
  --height NUMBER Selects the best format according to the video height.
  --audio-only Selects only audio formats.
  --video-only Selects only video formats.

2.2 ost

Downloads audio OSTs from the internet, optionally setting metadata for the downloaded files.

2.2.1 Options

Usage:
  jdv ost [OPTIONS] URL [FILE]
Short Long Note
-n --dry-run Prints only what will happen.
-t --title TITLE Embeds TITLE as the title metadata into the file.
-a --artist ARTIST Embeds ARTIST as the artist metadata into the file.
-A --album ALBUM Embeds ALBUM as the album metadata into the file.
-g --genre GENRE Embeds GENRE as the genre metadata into the file.

3.2 Overview

3.2.1 Getting Site Processor

The URL is matched with a list of site processors. A site processor in this context is defined as a Python module (acting as a singleton) that handles the process of extracting the info dictionary, then downloading and (possibly) renaming the output file.

3.2.2 URL Normalization

The site processor has a function for normalizing URLs, which is done before extracting the info dictionary. The exact method will change depending on the site processor (see Supported Sites).

3.2.3 Extracting Info Dictionary

Refer to Figure Figure 2.

The abstract method extract_info takes a URL and returns a SiteInfo, a dictionary-like object with a get_url method. It is intentially opaque, so only the site processor itself knows what to do with it. However, some parts of the dictionary are made visible via getter methods.

3.2.4 Selecting A Format

The abstract method select_format selects a suitable format based on the criteria provided by the user. This criteria comes in the form of a FormatSelector object.

A format is chosen from the dictionary via the strategy pattern. There are 5 strategies in total.

3.4 Supported Sites

3.4.1 Youtube

Notice

Right now, Youtube is the only site supported by Download Video. This will likely change in the future when this project has taken shape and is out of alpha.

The site processor for Youtube matches URLs with the following formats:

  • https​://www.youtube.com/watch?v=XXXXXXXXXXX
  • youtu.be/XXXXXXXXXXX
  • yt:XXXXXXXXXXX

This site processor normalizes the URL so that it always has the first form. The info dictionary returned by Youtube has this structure:

  1. URL Normalization

    URL normalization is done by matching a URL with a regular expression and capturing the video ID, then returning a "proper" URL with said video ID.

  2. Format Selection

    Selecting a format is done by trying to get the best (highest quality) video which satisfies the criteria outlined in FormatSelector (see Figure 2).

    A series of strategies are used to filter the list formats according to the criteria given. The name of each strategy class pretty much says what the strategy will be. Then the highest quality format is chosen. The barometer for a format's quality is its total bitrate, denoted in the tbr element.
